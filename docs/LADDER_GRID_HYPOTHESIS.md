# H-GRID1 — Ladder Grid (ตะแกรงหลายชั้น + TP ladder) บน XAUUSD

สถานะ: **เขียนโค้ดแล้ว ยังไม่ compile ใน MetaEditor และยังไม่มี backtest** (2026-09-29)
ที่มา: พฤติกรรมที่สังเกตได้จากหน้าประวัติไม้ของ EA เชิงพาณิชย์ตัวหนึ่ง (entry เรียงเป็นชั้นห่าง ~$10,
หลาย order ต่อชั้นที่ TP ต่างกัน) **ไม่ได้ถอดรหัสหรือลอกโค้ดของผู้ขาย** โลจิกทั้งหมดเขียนใหม่จากแนวคิดทั่วไป

## พฤติกรรมตลาดที่สมมติ
หลังราคายืดออกจากค่ากลางระยะสั้นมากผิดปกติ (วัดเป็นหน่วย ATR) ทองมีแนวโน้มดึงกลับบางส่วนภายในไม่กี่ชั่วโมง

## ทำไมอาจมีจริง
สภาพคล่องช่วงสวิงแรงหมดเร็ว, การปิดสถานะฝั่งที่ถูกบีบ, order flow ที่ไล่ราคาขาดแรงต่อ
(ยังเป็นเพียงคำอธิบาย ต้องพิสูจน์ด้วยข้อมูล)

## ควรทำงานเมื่อไร / ควรพังเมื่อไร
- ทำงาน: ช่วงตลาดวนกรอบ, สวิงเกินแล้วกลับ, สภาพคล่องปกติ
- พัง: เทรนด์ต่อเนื่องที่วิ่งผ่านทุกชั้น (ตะแกรงขาดทุนเต็มเพดานซ้ำ), ข่าวแรงที่ gap ทะลุ stop, spread ถ่าง
- **โครงสร้างผลตอบแทนแบบ "ชนะเล็กบ่อย แพ้เต็มเพดานนาน ๆ ครั้ง"** จึงต้องดู payoff, DD และความเข้มข้นของกำไรรายวัน
  ไม่ใช่ win rate

## ตัวแปรที่สังเกตได้ (ไม่มี look-ahead)
ระยะราคาจาก EMA ของแท่ง M5 ที่ปิดแล้ว หารด้วย ATR ของแท่งที่ปิดแล้ว, spread, ชั่วโมงเซิร์ฟเวอร์

## กฎที่เสนอ
1. เริ่ม basket เมื่อ Bid ≥ EMA + `stretch`×ATR (ขายสวน) หรือ Ask ≤ EMA − `stretch`×ATR (ซื้อสวน) และไม่มี basket ค้าง
2. ชั้น 0 เปิดที่จุดเริ่ม (anchor) ชั้น k เปิดเมื่อราคาสวนทางไป k×`step` (สูงสุด `max_levels` ชั้น ชั้นละครั้งเดียวต่อ basket)
3. แต่ละชั้นเปิดหลาย order ตาม `ladder` (TP = ตัวคูณ × step)
4. **basket stop** = anchor ± ((max_levels−1)×step + buffer) ตั้งเป็น SL ที่โบรกให้ทุก order
5. **lot คำนวณจากขาดทุนสูงสุดเมื่อชน basket stop** ≤ `risk_pct` ของ equity ถ้าต่ำกว่า lot ขั้นต่ำ → **ไม่เปิด** (ไม่ปัดขึ้น)
6. เพดานแข็ง: ขาดทุนสูงสุดต่อ basket ≤ `hard_risk_pct`, lot รวม, จำนวนไม้, spread, daily loss, max DD จาก peak

## ทำไมต้องคำนวณเพดานก่อน (ตัวเลขจากค่าเริ่มต้น)
ค่าเริ่มต้น step $10 / 3 ชั้น / 3 order ต่อชั้น / buffer $15 → basket stop ห่าง $35
ขาดทุนสูงสุดที่ 0.01 lot ต่อ order ≈ **$232** (spread+slippage เผื่อ $0.8 ต่อ order)
- ทุน $300 → 77% ของทุน → **ระบบปฏิเสธ**
- ต้องมีทุน ≈ **$11,600** ถึงจะเสี่ยง ≤ 2% ต่อ basket
ทุนเล็กที่ใช้ตะแกรงหลายชั้นได้ก็ด้วยการไม่คุมความเสี่ยง (กำไรมาจากวันที่ราคาไม่ไล่ต่อ) นี่คือประเด็นที่ EA ตัวนี้ต้องแก้

## วิธีหักล้าง (REJECT ถ้าเข้าเงื่อนไขใด ๆ)
- PF < 1.00 หลังต้นทุนจริง (spread + commission) บน Real Ticks
- PF ≥ 1.15 แต่กำไรกว่า 50% มาจาก ≤ 2 วัน
- OOS PF < 1.10 หรือ Max Equity DD > 15% ที่ risk_pct 2%
- edge หายเมื่อ spread +50% หรือ entry delay
- ablation: ถ้าตัด TP ladder หรือหลายชั้นออกแล้วผลดีกว่า ให้ตัดโมดูลนั้น

## ตัวแปรที่อนุญาตให้ปรับ (ไม่เกิน 2–4 ตัวต่อรอบ)
รอบ 1: `stretch_atr`, `step`  รอบ 2: `max_levels`, `ladder`  (ห้ามปรับ risk_pct เพื่อดันกำไร)

## Ablation ที่วางแผน
ทิศทาง (sell อย่างเดียว / buy อย่างเดียว / ทั้งสอง), 1 order ต่อชั้น vs ladder, 1 ชั้น vs หลายชั้น, ไม่มี stretch filter (สุ่มเข้า)

## รูปทรงความเสี่ยงจากข้อมูลสังเคราะห์ (ไม่ใช่หลักฐาน edge)
`python3 tools/ladder_grid_sim.py --synthetic` ทุน 20,000, lot 0.01/order, risk 2%

| เส้นทางราคา | capped (มี basket stop) | uncapped sell (ไม่มี stop, 10 ชั้น) ทุน 20k | uncapped ทุน 300 |
|---|---|---|---|
| ยืดแล้วดึงกลับ | +140 (DD 0.4%) | +140 (DD 0.4%) | +140 แต่ DD 25.8% ระหว่างทาง |
| ไล่ขึ้น 90 ใน 3 ชม. | −458 (DD 2.3%, stop 2 ครั้ง) | −1,244 (DD 6.3%) | equity ติดลบ (−948) |
| ไล่ขึ้น 180 ใน 8 ชม. | −980 (DD 5.0%, stop 4 ครั้ง) | −3,907 (DD 19.8%) | equity ติดลบ (−3,651) |

อ่านผล: เพดานทำให้ขาดทุนต่อ basket ถูกจำกัด แต่วันเทรนด์ยังกินทุน 2–5% จากการ stop ซ้ำ ส่วนตะแกรงไม่มีเพดาน
กำไรเท่ากันในวันที่ราคาดึงกลับ แต่วันไล่ราคาขาดทุนโตตามระยะที่ราคาวิ่ง และทุนเล็กรับ DD ระหว่างทางแม้ในวันที่ชนะ
ราคาของความปลอดภัยคือกำไรต่อทุนต่ำ (0.01 lot ต้องใช้ทุน ~$11.6k) ต้องดูว่าข้อมูลจริงให้ edge พอหรือไม่
